# Packet exp3_progressive: Progressive keys: a shift that grows by a fixed step per rune

Generated by `python -m lpswarm.research_packets` from development SHA f822be51e2e64c4979562e3cce497626c613f6e9 (Astra research note, 2026-11-05). Approval: **NO: review first, then ask**. Nothing has been run.

## What it tests

Decryption `p_t = c_t - k_t` or `p_t = k_t - c_t` (the reversed-alphabet form: what a reversed Gematria plus a shift looks like algebraically, as the source notes give for solved LP1 pages 1, 5 and 6; the interpreter's keyword for it is `beaufort`) with `k_t = d * s(o + t)` mod 29, where `s` is `naturals` (0, 1, 2, ...: an arithmetic progression, so each rune's shift grows by d), `squares` or `triangular`; d = 1..28 and the start offset o = 0..28. For `naturals` the offset sweep covers every constant term b, so this is the complete family `k_t = d*t + b`. Each proposal expands to 29 ciphers.

## Overlap with earlier work

- Single `naturals`, `squares` and `triangular` shifts with small scales may have been proposed by earlier model lanes (triangular with scale 1 appears in the section 19 near-miss list). Coverage is unknown until the local ledgers are compared.
- `add` is not generated: `add` with scale d equals `sub` with scale 29-d.
- `beaufort` is only the interpreter's keyword for `p = k - c`; using it here is a sign convention, not a claim about how the unsolved sections were enciphered.

## Not in this packet

- `squares` and `triangular` with a scale and a start offset are only a subfamily of quadratic keys (`a*t^2 + b*t + c`): the general quadratic or cubic polynomial key would need a new stream kind. It is not part of this packet.
- Combined with skips, maps or transpositions: this packet is the bare key.
